# تقرير الاختبارات وإعادة التشغيل

## النتائج المحلية

- **34/34 اختبارًا** عبر Vitest: إعدادات الحسابات، التحقق من القيم، عقود HTTP، مكونات React، وتحميل/حفظ صفحة الإعدادات.
- **8/8 اختبارات Chromium**: السيناريوهات الأربعة نفسها على سطح المكتب ومحاكاة شاشة/لمس Pixel 7.
- `npm run lint`: فحص TypeScript للمشروع والاختبارات ناجح.
- `npm run build`: بناء Vite للإنتاج ناجح.
- فُحص ملف القفل باستخدام npm 10 مع Node 22 لقبول التثبيت النظيف. `.npmrc` الأصلية ذات `legacy-peer-deps=true` محفوظة.

## ما جرى اختباره من المتصفح

الخادم المحلي يشغّل **مسارات الإعدادات والحسابات الحقيقية** من مستودع C، مع **MongoDB حقيقية محلية مؤقتة** عبر mongodb-memory-server. لا يَستبدل المتصفح API باستجابة مصطنعة؛ يرسل الطلبات إلى Express، الذي يحفظ الحالة والإعدادات في MongoDB. تُحاكى فقط استجابات خدمة حساب ChatGPT وخادم رفع الملفات باستخدام Nock داخل عملية الخادم.

| السيناريو | الأدلة التي يتحقق منها الاختبار |
|---|---|
| اختيار مشروع وإنشاء محادثة | يختار مشروعًا في الواجهة، يرسل رسالة إلى مسار الخادم، يفحص `conversation_mode.gizmo_id` في الطلب الخارجي، ويستقبل conversation ID |
| حفظ المهام واستعادتها | يحفظ محادثات مختلفة للترجمة والمصطلحات والمراجعة، يقرأ الوثيقة مباشرة من MongoDB عبر endpoint محلي للاختبار، ثم يعيد فتح الصفحة ويتحقق من القيم |
| Gemini وWorker | يفحص رقم Google صفرًا وترويسة النموذج ومعرّفات الاستمرار وtemperature صفرًا وmax_tokens والتفكير والبحث في بيانات MongoDB المحفوظة |
| المرفقات | يختار File من المتصفح، يمرره عبر multipart الفعلي إلى عميل الحساب، ويتحقق من معرّف المرفق في رسالة ChatGPT |
| المصادقة | الزائر لا يرى الإعدادات، والطلب إلى account API دون JWT يُرفض بـ401 |
| واجهة الهاتف | ينفذ السيناريوهات نفسها على قياسات Pixel 7، ويفحص عدم وجود تجاوز أفقي |
| بيانات الحساب | يتحقق من عدم كتابة توكن حساب AI في localStorage ومن خلو الصفحة من أخطاء JavaScript أثناء التدفق الرئيسي |

توكن JWT المستخدم في الاختبار مولد محليًا بمفتاح اختبار ثابت معروف داخل fixture، ولا يخص الموقع الحقيقي. لا تُستخدم بيانات الحسابات المرفقة سابقًا ولا كوكيز مستخدم حقيقية. مسارات `/__session` و`/__reset` و`/__evidence` موجودة في test harness فقط ولا تُنشر ضمن تطبيق Vite أو الخادم الإنتاجي.

## الاختبارات السريعة

```sh
npm ci
npm run lint
npm test
npm run build
```

يتحقق Vitest من فصل محادثات المهام، الحفاظ على الحقول الجديدة عند load/save، معرّف الحساب ومحددات Gemini والتفكير، الأصفار والحدود العددية وصحة JSPB وHTTPS، المشاريع والمحادثات والنماذج، رفع الملفات ومسحها بعد النجاح، الأخطاء دون تغيير المحادثة، ومنع الإرسال المكرر. كما يفحص Authorization وFormData وعدم إعادة POST وعدم تخزين بيانات المزود مؤقتًا في المتصفح.

## الاختبار المتكامل مع الخادم

يمكن وضع نسخة الخادم بجوار هذا المستودع أو في أي مسار خاص بك:

```sh
# In the backend checkout:
cd /path/to/C/backend
npm ci

# In the website checkout:
cd /path/to/New-moon-2
npx playwright install chromium
ACCOUNT_BACKEND_DIR=/path/to/C/backend npm run test:e2e
```

بديلًا عن متغير المسار، يمكنك وضع الخادم في `.test-backend/backend`؛ هذا المجلد مستثنى من git. الاختبار لا يحتاج بيانات MongoDB أو Firebase الإنتاجية؛ يحمل binary MongoDB لأول مرة ويستعمل قاعدة مؤقتة. يحتاج المنفذَين المحليين 4173 و4174.

ملف `.github/workflows/account-provider-tests.yml` يشغّل التثبيت وفحص الأنواع واختبارات React والبناء، ثم يجلب نسخة محددة من مستودع C ويشغل المتصفح والـAPI وMongoDB. القفل على commit `362a26425fab6ddea0d3157094008020c821a7f2` يثبت عقد الاختبار بدل تغيره صامتًا مع مستودع آخر.

## حدود النتيجة

- هذه اختبارات محلية متكاملة للواجهة مع مسارات الخادم والتخزين، وليست تجربة دخول إلى حساب ChatGPT أو Gemini أو DeepSeek حقيقي من الموقع المنشور.
- لم تتوفر جلسة إدارة للموقع الحقيقي لاختبار الكتابة في إعدادات الإنتاج، ولم تُستعمل بياناته من دونها.
- لم تُشغّل jobs كاملة مع Firestore الإنتاجية. تنفيذ الترجمة وفحص تغطية الفصل يخصان الخادم؛ تجربة Gemini الحية السابقة موثقة في [مستودع C](https://github.com/cobrapk8ggggggg-tech/C/blob/main/docs/testing.md).
- لم يتغير عنوان اتصال الموقع الافتراضي أو إعداد نشره، ولم يوضع توكن AI في متغير Vite عام.
- فحص فروع الترجمة والقراءة القديمة بالكامل ليس ضمن 42 اختبارًا جديدًا؛ توجد مراجعة بنيوية لبقية الملفات في `source-review.md` و`source-inventory.json`.
