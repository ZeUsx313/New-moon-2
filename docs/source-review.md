المراجعة اليدوية المفصلة ركزت على التطبيق والتوجيه والمصادقة وطبقة HTTP والإعدادات ووظائف الإدارة والترجمة وحدود التخزين والقارئ. الجرد البنيوي الشامل لا يعني تشغيل كل وظيفة وكل اتصال إنتاجي أو مراجعة أمنية كاملة لكل سطر.

## 1. تشغيل التطبيق والتوجيه

`index.html` هو shell عربي RTL يحمل الخطوط وبيانات SEO وmanifest ويسجّل Service Worker. نقطة التشغيل الفعلية `main.tsx`: تحمل CSS، تهيئ Google Analytics الاختيارية وبديل الأغلفة، ثم تركّب App. يوجد أيضًا `index.tsx` قديم لكنه ليس script المستخدم في HTML.

`App.tsx` يركب ErrorBoundary وHelmet وReact Query والمظهر والمصادقة وحالة الواجهة، ثم BrowserRouter. الصفحات محملة بـ React.lazy؛ صفحات الإدارة من ملفات متعددة الوظائف، وكل Route يختار export معينًا. Footer مشروط بالمسار وBottomNav يختفي في القارئ/الرواية/العضو وفق سياسة الموقع.

`vite.config.ts` يضبط React وTailwind 4 وalias والبناء. `vercel.json` يعيد مسارات SPA إلى HTML، ويوجه sitemap إلى الخادم، ويضبط ترويسات المتصفح والتخزين للأصول. لا يوجد كود خادم AI داخل مستودع الموقع.

## 2. الخادم والمصادقة وطبقة الخدمات

`src/services/api.ts` يختار `VITE_API_URL` أو عنوان الخادم الأصلي. `src/lib/http.ts` هو المسار المشترك: fetch، AbortController، تحليل JSON آمن، Authorization من جلسة الموقع، رؤوس captcha/reader session، وإعادة محاولات GET فقط افتراضيًا. FormData يمر دون Content-Type يدوي حتى يبني المتصفح boundary صحيحًا.

`AuthContext.tsx` يعيد التحقق من جلسة الدخول عبر `/api/user`، ويحذف الرمز عند 401/403 ويحتفظ به مع فشل الشبكة، ويزامن التبويبات عبر StorageEvent. `services/auth.ts` يغطي الدخول والتسجيل وGoogle وتغيير كلمة المرور. Login/Signup/GoogleCallback تعتمد على هذه الطبقة. `ThemeContext` يفرض الوضع الداكن عمدًا؛ `UIContext` ينسق درج Header وإخفاء التنقل السفلي.

| الخدمة | ما تتصل به |
|---|---|
| `admin.ts` | CRUD الروايات والفصول والإدارة والرفع والأدوار |
| `translator.ts` | المترجم والمراجع والمستخرج والمترجم الخالص وبيانات الرواية والعناوين والحقوق والسكرابر |
| `novel.ts` | الروايات وقوائم الفصول والمحتوى والتفاعلات والمكتبة وتقدم القراءة |
| `user.ts` | الملف الشخصي والإحصاءات والملف العام ورفع الصور |
| `category.ts` | التصنيفات |
| `comment.ts` | التعليقات والردود والتفاعلات |
| `accountProviders.ts` الجديد | مسارات حسابات المزودين؛ يستخدم HTTP نفسه ولا يتجاوز الخادم |

## 3. القراءة والمحتوى والتخزين

`Home.tsx` للتصفح والبحث والقوائم. `NovelPage.tsx` يدير وصف الرواية والفصول والبحث والترقيم والتفاعل والناشر والتعليقات والتنزيل؛ وصف HTML يمر عبر DOMPurify. `Library` و`HistoryPage` و`Downloads` و`MyPage` و`UserProfile` تبني واجهات المكتبة والتقدم والعضوية. StaticPages وNotFound تغطي الصفحات العامة.

`Reader/index.tsx` غلاف لـ `Reader/wor/WorReader.tsx`. القارئ يجلب النص offline-first، يطبق الاستبدالات والإعدادات والحماية النصية، ويرسل البيانات إلى iframe يستعمل `srcDoc` من `reader/worShell.js`. رسائل iframe تتعامل مع التمرير والتنقل والفصل التالي والإعدادات والتعليقات والمفضلة والبلاغات. يحفظ موضع القراءة ويزامن التقدم، ويدعم القراءة المستمرة مع جلب الفصل التالي. `sections.ts` و`worCSS.js` و`worFonts.js` و`wordsStore.js` تكمل قالب القراءة وإعدادات الكلمات والخطوط.

`lib/offlineStore.ts` يستخدم IndexedDB للكتب والفصول؛ `offlineDownloads.ts` يدير التنزيل والاستئناف والإلغاء وتحديد التزامن والتهدئة. `reader/storage.ts` بديل AsyncStorage فوق localStorage مع احتياط في الذاكرة. `apiCache.ts` يدعم ذاكرة وsessionStorage مع TTL وتجميع الطلبات المتطابقة. `storage.ts` يوفر قراءة JSON لا تتعطل مع قيمة تالفة.

`public/sw.js` يستخدم network-first لقشرة التطبيق وcache-first للأصول ذات الأسماء المجزأة والصور. يستثني `/api/` و`/auth/` من التخزين. لذلك الإعدادات الجديدة لا تُخزن في Service Worker.

## 4. لوحة التحكم ووظائف AI

`DashboardLayout.tsx` ينظم قائمة سطح المكتب ودرج الجوال وأقسام المترجمين والإدارة. `shared.tsx` يحتوي StaffGate وModal وأنماط النماذج وبعض عناصر الروايات. Header يعيد تقديم روابط الأدوار في التنقل العام.

| الملف | الوظائف |
|---|---|
| `CorePages.tsx` | الروايات وإنشاؤها وتعديلها والفصول والنشر الجماعي ZIP وإدارة المسرد |
| `AiPages.tsx` | مهام الترجمة وبدء المهمة والتفاصيل والطرفية وتعريب البيانات وإعدادات المزودين |
| `ReviewPages.tsx` | بدء المراجعة ومهامها وتفاصيلها ونتائج الفصول المعلّمة |
| `GlossaryAiPages.tsx` | استخراج مصطلحات الرواية قبل الترجمة |
| `PureTranslationPages.tsx` | ترجمة الفصول بالمسرد دون استخراج إضافي |
| `TitleGenPages.tsx` | توليد العناوين وإعداداته وإصلاح/استخراج العناوين |
| `AdminPages.tsx` | المستخدمون والتصنيفات والسجلات والتحليلات والأمان والمنظف والحقوق والسكرابر |

جميعها ترسل أوامر إلى الخادم وتقرأ وظائفه وسجلاته؛ لا تنفذ الترجمة في المتصفح. شكل طلبات المهام لم يحتج إلى تغيير حتى تستفيد من مزودي الخادم الجدد؛ الموضع الذي احتاج التعديل هو واجهة إعدادات المزودين وعمليات إدارة حساباتهم.

## 5. المشاكل المرتبطة بهذا التعديل وما أصلح

1. تحميل الإعدادات كان يعيد بناء كل مزود بقائمة حقول قديمة. هذا يسقط `taskConversations` وإعدادات Gemini والحساب والتفكير والمعاملات الجديدة.
2. الحفظ يعيد بدوره بناء المزود بقائمة قديمة، فيحذف اختيارات المشاريع والمحادثات حتى لو وصلتها الواجهة من الخادم. أضيف اختيار موحد لحقول الحساب بين التحميل والحفظ مع نسخ حالة المهام دون مشاركة مرجعها.
3. ChatGPT وقالب Worker لم يكونا موجودين. أضيفت القوالب بعناوين ونماذج افتراضية صحيحة، مع إبقاء المخصص مستقلًا حسب providerId.
4. Worker يطابق بادئة `deepseek_` المستخدمة للقالب القديم. استُثني من أزرار expert/POW وأعطي حقوله الخاصة؛ أضيف 3MH أيضًا لقائمة POW القديمة كخيار مستقل.
5. Gemini كان يعرض أن فراغ الكوكيز يعني وضع الضيف تلقائيًا. وُحدت الواجهة مع سلوك الخادم الجديد الذي يتطلب تفعيل guest fallback صراحة، وأضيف رقم الحساب وحالة المحادثة وبقية الحقول المثبتة.
6. غابت وسائل جلب مشاريع ChatGPT وإنشاء محادثة فيها ورفع المرفقات. أضيف مكون مستقل مكتوب بـTypeScript مع labels وحالة انتظار وأخطاء وتحديث المهمة المقصودة.
7. أزرار الحفظ أعلى وأسفل الصفحة قد تعمل أثناء إنشاء محادثة لم يعد معرّفها بعد. أصبحت معطلة حتى يكتمل الطلب.
8. لم يكن ملف قفل npm متتبعًا، ولم تكن أنواع React مصرحًا بها مباشرة. أضيف القفل وأنواع React وأدوات الاختبار لضمان تثبيت وبناء قابلين لإعادة التشغيل.

## 6. ملاحظات أصلية خارج نطاق تعديل المزودين

- إخفاء روابط الإدارة عن contributor في القائمة ليس قفلًا لمسارها. StaffGate يقبل المساهم والمشرف، والتحقق النهائي يخص الخادم. يلزم توحيد سياسة الأدوار قبل أي تعديل للصلاحيات؛ لم يغير هذا العمل أدوار المستخدمين.
- iframe القارئ يسمح `allow-scripts allow-same-origin`، ورسائل المصدر تفحص `event.source` وتستخدم مقارنة hostname جزئية للـorigin. يمكن تدقيق حدود HTML والمصدر والأصل في عمل مستقل.
- `readerSession.ts` يبني عنوان الإصدار من متغير البيئة أو المسار النسبي، بينما API_BASE_URL له افتراضي خادمي صريح. لذلك إعداد `VITE_API_URL` مهم عند النشر لتجنب اختلاف مجال جلسة القراءة. لم يغير هذا العمل آلية القراءة.
- القالب يحتوي placeholder لمفتاح Google verification؛ يظهر تنبيه Vite إذا لم يضبط متغيره الاختياري.
- بعض وظائف السجلات والمهام تعتمد polling بدل تحديث دفع؛ تدفق بيانات الخادم وحدود auth/الأخطاء يجب الحفاظ عليها عند أي إعادة تنظيم مستقبلية.
- حماية النص وفك تمويهه في المتصفح ليست تخزينًا سريًا؛ لم تُستخدم مفاتيح التمويه لحفظ بيانات حسابات AI.

## 7. حدود التحقق

فُحص النوع والبناء للموقع كله. اختُبرت ميزة الحسابات بوحدات React وعقد HTTP وبمتصفح Chromium لسطح المكتب والجوال مع مسارات الخادم المعدل وMongoDB حقيقية محلية. محاكاة المزود الخارجي مقصودة ولا تمثل اختبار حسابات ChatGPT أو DeepSeek الحقيقية. لم تُشغّل jobs إنتاجية مع Firestore ولم تُراجع كل وظيفة قديمة عبر حسابات مستخدمين حقيقية.
